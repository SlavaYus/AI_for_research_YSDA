## Что пошло не так и как исправлено

| Сессия | Что вышло | Исправление в `AGENTS.md` |
|---|---|---|
| 1 | агент посчитал числа во временном файле вне проекта и только потом записал задачи | «запиши задачу и подзадачи до любых расчётов»; «расчёты — скриптами в `src/`, временных файлов вне проекта не создавай» |
| 1 | статусы «в работе» не ставились; «выполнена» — всем подзадачам в конце | «статус меняется в момент события: «в работе» — до первой команды подзадачи, «выполнена» — сразу после проверки её условия» |
| 1 | связь `основанаНа` вела к файлу `library/…` вместо заметки источника; скрипт сообщил о несогласованной связи, агент исправил сам | правило «источник — заметка с `хранитсяВ: [[library/…]]`» |
| 2 | отчёт привязан связью `выполняет` к принятой задаче; своей задачи отчёт не получил. Скрипт этого не ловит: видно при чтении графа | «каждое сообщение с новой работой — новая задача»; «принятая задача закрыта: новые связи `решает` и `выполняет` к ней не добавляются» |
| 2 | ссылки `[[…]]` в тексте отчёта взяты в обратные кавычки: Obsidian их не показывает; источники названы только в разделе «Связи» | «ссылки не берутся в обратные кавычки»; «утверждение из источника — со ссылкой на заметку источника в тексте» |

Результаты в `demo_graph_result/` получены до этих уточнений; `AGENTS.md` в стартовом
наборе и в результатах — уточнённый.

Вывод для своего проекта: правило, которое агент нарушил, становится строкой в
`AGENTS.md`. Часть нарушений ловит скрипт, остальные — чтение графа человеком; поэтому
статус «принята» ставится только по словам пользователя.

## Своя онтология и граф

- Шаблон без заполнения: «[НЕТ] в онтологии остались незаполненные места шаблона».
- Онтология готова, агент ещё не запускался: «[НЕТ] объектов с типом — 0», «[ГРАФ]
  классы без заметки в ontology/» (с `--strict` — ошибка).
- Частые сообщения первой сессии: «несогласованная связь» (связь записана не в той
  заметке или не к тому классу), «[ПРАВИЛО]» — в графе не хватает связи, которой
  требует правило, «объекты без строки «- тип: [[Класс]]»», «Задача без поля
  «status»», «атрибут status: значения нет в онтологии».

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `Нужен пакет PyYAML` | `python3 -m pip install pyyaml` |
| в Obsidian не видны файлы данных и кода | Settings → Files & links → Detect all file extensions; в виде «Граф» — Filters → Attachments |
| узлы одного цвета | Graph view → Groups: запросы `path:ontology`, `[status:открыта OR "в работе" OR заблокирована]`, `path:tasks`, `[type:Эксперимент OR Проверка]`, `path:notes OR path:reports` |
| «заметки во вложенных папках notes/» | в названии был символ `/`; переименуйте без него и поправьте ссылки |
| «заметка объекта названа как класс» | переименуйте в название экземпляра: «Образец S7» |
| «связь … ведёт к классу» | к классу ведёт только `тип`; замените ссылку на экземпляр |
| «несогласованная связь» | перенесите строку в заметку, от которой идёт связь, или исправьте тип заметки |
| «П9 … нарушено» | родительская задача отмечена выполненной при невыполненной подзадаче: верните ей статус «в работе» или закончите подзадачу |
| «П10 … не найдено» | у выполненной задачи нет раздела «## Итог» |
| агент сделал больше, чем просила задача | уточните «Готово, когда» и «Не входит» в сообщении; объём задаёт заметка задачи |
| агент закончил, а статусы остались «открыта» | напишите в сессии «обнови статусы задач по разделу 2.4 AGENTS.md» |
