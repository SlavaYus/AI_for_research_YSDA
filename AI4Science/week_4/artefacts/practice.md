# Неделя 4. Самостоятельная практика: онтология и граф проекта

Курс «ИИ-ассистенты для исследователя. AI4Science».

**Результат недели:** ваш проект — хранилище Obsidian, в котором весь проект образует
граф: онтология `ontology.yaml` и заметки её классов в `ontology/`, заметки объектов
работы в `notes/` с типами и связями, ссылки на файлы данных, кода и результатов.
`AGENTS.md` содержит раздел «Граф проекта», по которому агент сам ведёт задачи и
достраивает граф: вы ставите задачи словами в сессии, агент записывает их в `tasks/`,
делит на подзадачи, ведёт статусы и сообщает итоги. Граф пережил две сессии;
проверка `check_week4.py` проходит; всё в git.

**Время:** 3–5 часов.

**Что нужно заранее:**
- учебный агент: `ai4science doctor` проходит без ошибок;
- проект в git-репозитории с `AGENTS.md`;
- Python 3 и пакеты PyYAML и numpy: `python3 -m pip install pyyaml numpy`;
- Obsidian — бесплатная программа для заметок, https://obsidian.md. Без Obsidian граф
  можно посмотреть как схему Mermaid (шаг 5).

Все команды выполняются в терминале Linux, macOS или WSL.

## Что вы делаете и зачем

**Онтология** — система классов, отношений и правил, описывающая предметную область
для заданной цели. В проекте она живёт в двух местах: `ontology.yaml` — схема, которую
читают агент и скрипт проверки; `ontology/<Класс>.md` — схема онтологии в виде заметок,
чтобы классы были узлами графа.

**Граф проекта** — три слоя узлов:

| Слой | Где | Пример | Как связан |
|---|---|---|---|
| классы (TBox) | `ontology/` | `Эксперимент`, `НаборДанных` | `подклассОт` |
| объекты (ABox) | `tasks/`, `notes/`, `reports/` | «Рассчитать E_a по трём сериям» (задача), «Расчёт E_a по трём сериям» (эксперимент) | `тип` — к классу; отношения онтологии — к другим объектам |
| файлы | весь проект | `data/raw/rates.csv`, `src/fit.py` | `хранитсяВ`, `реализованВ` — от объекта к файлу |

`AGENTS.md` и онтологию вы пишете один раз; дальше управляете агентом сообщениями в
сессии. Агент записывает каждую задачу заметкой в `tasks/`, делит её на 2–5 подзадач,
ведёт поле `status` (открыта → в работе → выполнена или заблокирована), по каждой
подзадаче пишет раздел «Итог» и по правилам `AGENTS.md` записывает объекты и связи.
Статус «принята» агент ставит только после ваших слов в сессии: принять результат
может только человек. Решение о новых классах онтологии тоже за вами.
Скрипт проверяет, что концы каждой связи согласованы с онтологией — это **локальная**
согласованность; глобальной машины вывода в проекте нет.

## Шаг 1. Демонстрация: две сессии (40 мин)

**1.1. Готовый результат.** Откройте в Obsidian папку `demo_graph_result/iter2` как
хранилище (Open folder as vault) и вид «Граф» (Graph view). Серые узлы — классы,
оранжевые — задачи, которые ждут работы или решения, жёлтые — выполненные и принятые
задачи, зелёные — эксперименты и проверки, синие — остальные объекты и отчёт, узлы без
цвета — файлы проекта. Если файлы не видны: Settings → Files & links → Detect all file
extensions; в виде «Граф» — Filters → Attachments.

**1.2. Подготовка.**

```bash
cp -r demo_graph ~/w4demo && cp check_week4.py ~/w4demo/ && cd ~/w4demo
git init -q && git add -A && git commit -qm "исходное состояние"
chmod -R a-w data library ontology.yaml check_week4.py
```

**1.3. Сессия 1: задача.** Запустите агента и напишите ему сообщение:

```bash
ai4science --no-lean --mode auto
```

```text
Проверь, подчиняется ли разложение закону Аррениуса в интервале 25–70 °C, и найди
энергию активации по data/raw/rates.csv. Результат проверь независимым пересчётом.
```

Агент записывает задачу и подзадачи в `tasks/` и показывает план, затем выполняет
подзадачи по очереди. По каждой он сообщает итог и пишет раздел «Итог» в её заметке.
По ходу работы создаёт `.obsidian/`, заметки классов, заметки серий, эксперимента,
результата, проверки и ограничения со ссылками на `data/raw/rates.csv`, `src/…`,
`results/…`. Когда агент закончит, выйдите из сессии (`/exit`) и сохраните состояние:

```bash
python3 check_week4.py --strict
git add -A && git commit -qm "сессия 1: проверка закона Аррениуса"
```

Режим `--mode auto` разрешает агенту действия без подтверждения: подходит для учебного
проекта, где данные закрыты от записи. В своём проекте начните с режима по умолчанию.

**1.4. Сессия 2: приёмка и отчёт.** Откройте задачи в Obsidian или прочитайте разделы
«Итог». Новая сессия начинается с чтения `tasks/`: агент знает, что сделано, без
истории прошлого разговора.

```bash
ai4science --no-lean --mode auto
```

```text
Проверку принимаю. Подготовь для коллег отчёт с графиком и ссылками на источники из library/.
```

Агент ставит первой задаче статус «принята» с вашими словами в итоге, заводит задачу
«отчёт», пишет его в `reports/` и связывает с экспериментом, результатом и
источниками. Прежние узлы остаются на месте: граф дополняется.

```bash
python3 check_week4.py --strict
git add -A && git commit -qm "сессия 2: отчёт"
git diff --stat HEAD~1
```

**Чек-пойнт.** `git diff --stat HEAD~1` показывает новые заметки и смену статусов;
проверка проходит; в выводе проверки — задачи по статусам.

## Шаг 3. Онтология в YAML (60 мин)

```bash
cp ~/путь/к/стартовому/набору/ontology_template.yaml ontology.yaml
cp ~/путь/к/стартовому/набору/check_week4.py .
```

- **Классы** — не меньше трёх: надкласс (`parent`) или `null`, определение
  (`definition`). Добавьте классы `Задача` и `Файл`: заметки задач и файлы проекта.
- **Отношения** — у каждого `domain` и `range`; связи с файлами — отдельными
  отношениями, например `хранитсяВ` с `range: Файл`.
- **Атрибут** `status` у класса `Задача` со списком значений; отношение `подзадачаОт`.
- **Правила** — не меньше двух, словами (`text`) и в дескрипционной логике (`dl`); поле
  `check` — чтобы скрипт проверял правило на графе.

| Правило словами | Запись DL | Вид проверки |
|---|---|---|
| каждый эксперимент проверяет хотя бы одну гипотезу | `Эксперимент ⊑ ∃проверяет.Гипотеза` | `some` |
| каждый результат получен в эксперименте | `Результат ⊑ ∃даёт⁻.Эксперимент` | `some_inverse` |
| принятый результат — результат, прошедший проверку | `ПринятыйРезультат ≡ Результат ⊓ ∃проверенЧерез.Проверка` | `defined` |
| выполненная задача — задача со статусом «выполнена» или «принята» | `ВыполненнаяЗадача ≡ Задача ⊓ ∃status.{выполнена, принята}` | `defined_value` |
| выполненную задачу закрывает эксперимент, проверка, отчёт или подзадачи | `ВыполненнаяЗадача ⊑ ∃решает⁻.⊤ ⊔ ∃выполняет⁻.⊤ ⊔ ∃подзадачаОт⁻.⊤` | `some_inverse_any` |
| задача выполнена, только если выполнены все её подзадачи | `ВыполненнаяЗадача ⊑ ∀подзадачаОт⁻.ВыполненнаяЗадача` | `all_inverse` |
| у выполненной задачи есть раздел «Итог» | — (оформление) | `section` |
| результат не подтверждает и не опровергает одну гипотезу одновременно | `DisjointObjectProperties(подтверждает опровергает)` | `disjoint_properties` |

Сверьте онтологию с вопросами шага 2: каждый класс и каждое отношение нужны хотя бы
одному вопросу.

```bash
python3 check_week4.py
```

**Чек-пойнт.** В блоке «Онтология» все строки «[OK]».

## Шаг 4. AGENTS.md ведёт задачи и граф (60 мин)

**4.1. Раздел «Граф проекта».** Перенесите в свой `AGENTS.md` разделы 0, 2, 4, 5 из

- заметки объектов `notes/<название>.md`: `type`, строка `- тип: [[Класс]]`, связи по

- задачи: заметка `tasks/<действие>.md` с «Запросом пользователя», «Готово, когда»,

**4.2. Сессия 1.** Закройте `data/raw/`, `ontology.yaml`, `check_week4.py` от записи,

```bash

```

**4.3. Сессия 2.** Новая сессия: примите результат словами (или попросите переделать)

**4.4. Новые типы.** Если агент завёл тип, которого нет в онтологии, скрипт выдаст
«[СОВЕТ] типы, которых нет в онтологии». Решите сами: внести класс в `ontology.yaml`
(при следующем запуске агент создаст заметку класса) или заменить тип в заметке.

**Чек-пойнт.** Не меньше десяти объектов, у каждого связь с классом; у задач — статусы

## Формат ontology.yaml

| Поле | Что в нём |
|---|---|
| `ontology`, `goal` | имя и цель: на какие вопросы отвечает граф |
| `competency_questions` | 3–5 вопросов |
| `classes` | `Имя: {parent: Надкласс или null, definition: признак}` |
| `properties` | `имя: {domain: Класс или [список], range: Класс или [список], characteristics: [...]}` |
| `attributes` | `имя: {domain: Класс, values: [значение, …]}` — поле в начале заметки |
| `rules` | `id`, `text`, `dl`, по желанию `check` |

## Примеры по дисциплинам

| Дисциплина | Классы | Отношение | Правило |
|---|---|---|---|
| Физика | Установка, Калибровка, Измерение, Серия, Файл | `калиброванаЧерез`: Установка → Калибровка | `Измерение ⊑ ∃выполненоНа.Установка` |
| Химия | Вещество, Реакция, Опыт, Спектр, Файл | `участвуетВ`: Вещество → Реакция | `Опыт ⊑ ∃изучает.Реакция` |
| Биология | Образец, Организм, Секвенирование, Прочтения, Файл | `взятИз`: Образец → Организм | `Прочтения ⊑ ∃хранятсяВ.Файл` |
| Науки о Земле | Станция, Ряд, ПереносСтанции, Поправка, Файл | `измеренНа`: Ряд → Станция | `ОднородныйРяд ≡ Ряд ⊓ ¬∃затронут.ПереносСтанции` — правило открытого мира, скрипт его не проверяет |
| Математика | Утверждение, Доказательство, Определение, Файл | `опираетсяНа`: Утверждение → Утверждение, транзитивное | `ДоказанноеУтверждение ≡ Утверждение ⊓ ∃имеет.Доказательство` |

## Типовые ошибки

- **Граф в отдельной папке.** Хранилище открыто на `notes/`: файлы данных и кода в
  граф не попадают. Хранилище — корень проекта.
- **Онтология только в YAML.** Без заметок классов объекты в графе не связаны с
  классами; скрипт сообщает «классы без заметки в ontology/».
- **Экземпляр в онтологии.** «Серия 2024-01» записана классом.
- **Заметка названа как класс.** Заметка «Образец» с типом `Образец`.
- **Ссылка на класс отношением.** `- относитсяК: [[Образец]]` вместо `[[Образец S7]]`;
  к классу ведёт только `тип`.
- **Связь против направления.** `- использует:` в заметке набора данных, хотя область
  определения — Эксперимент.
- **Файл без пути.** `[[rates.csv]]` при двух файлах с таким именем; ссылка на файл —
  по пути от корня.
- **Задача без проверяемого условия.** «Готово, когда: разобраться с данными» — агент
  закроет такую задачу когда угодно. Условие называет файл, число или команду.
- **Статус без итога.** «выполнена» без раздела «Итог»: не видно, чем проверено.
- **Ожидание закрытого мира от правила.** `Статья ⊑ ≥2 имеетРецензию.Рецензия` в
  онтологии не находит статьи с одной рецензией; полноту записи проверяет скрипт.

## Артефакт недели 4

- **Что сделать:** онтология (≥3 класса, ≥2 правила) + мини-граф (≥10 узлов).
- **Минимум для «зачтено»:** не меньше трёх классов и двух правил; не меньше десяти
  объектов графа, каждый связан со своим классом; нет путаницы «класс / экземпляр»;
  связи согласованы с областями определения и значений; всё в git.
- **Идёт в:** домашнюю работу 1 «Среда и контекст» (сдача к неделе 6).
- **Время:** 3–5 ч.
- **Стартовый набор:** `demo_graph/`, `demo_graph_result/`, `ontology_template.yaml`,
  `check_week4.py`.
- **Где лежит у вас:** `ontology.yaml`, `ontology/`, `notes/`, `tasks/` (задачи со
  статусами и итогами) и `.obsidian/` в корне проекта; раздел «Граф проекта» в
  `AGENTS.md`.
- **Самопроверка:**
  1. `python3 check_week4.py; echo $?` — последняя строка «Все обязательные пункты
     выполнены», код 0;
  2. `ls ontology/*.md | wc -l` — столько же, сколько классов в `ontology.yaml`;
  3. `grep -l "^- тип: \[\[" notes/*.md | wc -l` — не меньше 10;
  4. `grep -h "^status:" tasks/*.md | sort | uniq -c` — статусы задач;
     `grep -c "^## Итог" tasks/*.md` — у каждой выполненной или принятой задачи 1;
  5. `git log --oneline | head -3` — коммиты сессий;
  6. `git status --short` — пустой вывод.
- **Пример по дисциплинам:** таблица выше; учебный пример — химическая кинетика
  (`demo_graph/`).
- **Типовые ошибки:** дополняется после разбора на следующей лекции.
