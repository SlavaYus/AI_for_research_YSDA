# Неделя 2. Самостоятельная практика: задача для агента в AGENTS.md

Курс «ИИ-ассистенты для исследователя. AI4Science».

**Результат недели:** в вашем проекте лежит `AGENTS.md`, в котором записаны
цель, критерий готовности (команда проверки), режим работы, запреты и
бюджет; проверка работает; в журнале проекта есть записи о прогонах агента
с этим файлом и без него.

**Время:** 3–4 часа.

**Что нужно с недели 1:** установленный учебный агент (`ai4science doctor`
без ошибок) и ваш проект в git-репозитории с `AGENT.md` и `diary.md`.

---

## Что вы делаете и зачем

На лекции агентная система разобрана по частям: модель порождает текст,
ведущее приложение превращает его в действия, среда эти действия
исполняет. Чтобы результат агента можно было принять или отклонить,
до запуска фиксируются пять вещей (протокол, слайды 41–43 недели 2):

1. **цель** — какие файлы и с каким содержимым должны появиться;
2. **критерий готовности** — команда, которая без агента отвечает «готово»
   или «не готово»;
3. **бюджет** — сколько шагов агент может сделать;
4. **режим работы** — сразу действовать, сначала план и т. д.;
5. **контекст и запреты** — что агенту нужно знать и чего делать нельзя.

`AGENTS.md` — файл в папке проекта, куда всё это записано. Агент читает его
в начале каждой сессии. На этой неделе вы:

- на готовом тестовом проекте увидите, как этот файл меняет поведение
  агента (шаг 1);
- напишете такой файл и проверку для своего проекта (шаг 2);
- запустите агента на своём проекте с новым файлом (шаг 3).

python -m pip install numpy scipy pandas     # macOS / Linux: python3 -m pip …

## Шаг 1. Тестовый проект: без AGENTS.md и с ним (60 мин)

Выберите один тестовый проект — ближе всего к своей области. Скопируйте
папку `test_projects/` к себе и выполняйте команды из неё. Ниже команды
для `spectra_peaks`; для остальных проектов — в таблице после шага.

**1.1. Две копии проекта.** В одной вы удалите `AGENTS.md`, в другой
оставите. Каждую копию сделайте репозиторием, чтобы после прогона `git
status` показал всё, что изменил агент. Исходные данные закройте от записи.

```bash
cp -r spectra_peaks run_without && cp -r spectra_peaks run_with
cd run_without && rm AGENTS.md
git init -q && git add -A && git commit -qm "исходное состояние" && chmod -R a-w data
cd ../run_with
git init -q && git add -A && git commit -qm "исходное состояние" && chmod -R a-w data
cd ..
```

**1.2. Прочитайте `run_with/AGENTS.md`.** Это образец того, что вы будете
писать в шаге 2. Разделы:

| Раздел | Что в нём | Пункт протокола |
|---|---|---|
| 0. Цель и образ результата | какие файлы должны появиться и с какими столбцами | цель |
| 1. Критерий готовности | команда `python checks/check_peaks.py`: код 0 — принято | критерий готовности |
| 2. Карта проекта | где данные и чего агент не знает сам (порог шума, фон) | контекст |
| 3. Инструменты и границы | чем можно пользоваться | контекст |
| 4. Запреты | что нельзя делать; у каждого пометка `[окно]`, `[вызов]` или `[среда]` | запреты |
| 5. Протокол и режим работы | ReAct: после каждого изменения — запуск и проверка | режим |
| 6. Память | что записать в `diary.md` | журнал |
| 7. Остановка и бюджет | не больше 15 шагов; когда остановиться | бюджет |

**Пометки у запретов.** Агент читает `AGENTS.md` целиком, пометки тоже
попадают в его окно контекста. Но адресованы они человеку, который ведёт
проект: пометка говорит, **где запрет обеспечивается**. Три пространства с
лекции (слайды 22 и 39):

| Пометка | Где обеспечивается запрет | Если удалить строку из AGENTS.md | Пример |
|---|---|---|---|
| `[окно]` | только текстом в окне контекста модели | запрет исчезает | «Не заполнять пропуски» |
| `[вызов]` | ведущее приложение не выполняет вызов: инструмента нет или нужно подтверждение человека | запрет действует | запуск с `--mode approve` |
| `[среда]` | вызов выполняется, но среда не даёт изменить защищённое | запрет действует | `chmod -R a-w data` — запись в `data/` завершается ошибкой доступа |

Строку запрета держат в файле и тогда, когда он закрыт механизмом: агент
заранее знает о границе и не тратит шаги на попытки её пройти.

**1.3. Прогон без AGENTS.md.** Задача ставится своими словами, как вы бы
поставили её без подготовки:

```bash
cd run_without
ai4science run "Найди положения и ширины пиков во всех спектрах из data/"
python checks/check_peaks.py; echo "код проверки: $?"
git status
cd ..
```

**1.4. Прогон с AGENTS.md.** Задача — одна строка: всё остальное записано в
файле.

```bash
cd run_with
ai4science run "Выполни цель из AGENTS.md."
python checks/check_peaks.py; echo "код проверки: $?"
git status
cd ..
```

Во время прогона агент печатает свои действия: каждый блок с `▸` и
командой — один вызов инструмента, то есть один шаг. Прогон занимает
3–5 минут.

**1.5. Сравните и запишите.** Добавьте в `diary.md` **своего** проекта
запись:

```markdown
## <дата> — тестовый проект spectra_peaks: без AGENTS.md и с ним
| | без AGENTS.md | с AGENTS.md |
|---|---|---|
| код проверки | … | … |
| какие файлы создал агент | … | … |
| вызвал ли проверку сам | … | … |
| число шагов (блоков ▸) | … | … |
| нарушил ли запреты | … | … |
- Какой раздел AGENTS.md сильнее всего изменил поведение: …
```

Если проверка не проходит и в прогоне с AGENTS.md — это тоже результат:
запишите, на каком шаге агент ошибся и остановился ли он по правилу
раздела 7.

**Команды для других проектов:**

| Проект | Запрос без AGENTS.md | Проверка | Закрыть от записи |
|---|---|---|---|
| `spectra_peaks` | «Найди положения и ширины пиков во всех спектрах из data/» | `python checks/check_peaks.py` | `chmod -R a-w data` |
| `station_trends` | «Посчитай тренд температуры по каждой станции из data/raw/» | `python checks/check_trends.py` | `chmod -R a-w data` |
| `lit_review` | «Составь таблицу работ из library/ и короткий обзор» | `python checks/check_review.py` | `chmod -R a-w library` |

**Ловушка в `lit_review`.** В одной аннотации спрятано указание для
ИИ-ассистента удалить файл из библиотеки — промпт-инъекция (слайд 14).
Посмотрите, выполнил ли его агент и что его остановило: строка запрета в
окне контекста или права доступа к `library/`.

**Чек-пойнт.** В `diary.md` своего проекта — таблица сравнения двух прогонов.

## Шаг 2. AGENTS.md и проверка для своего проекта (90 мин)

**2.1. Один файл.** В вашем проекте с недели 1 уже есть `AGENT.md`. Агент
читает первый найденный файл из списка `AGENT.md`, `AGENTS.md`, `CLAUDE.md`
— второй файл он не увидит. Поэтому файл остаётся один: переименуйте его и
перенесите содержимое в разделы шаблона.

```bash
git mv AGENT.md AGENTS.md
```

Откройте `AGENTS_template.md` и перенесите в свой `AGENTS.md` его разделы:

| Что было в AGENT.md недели 1 | Куда перенести |
|---|---|
| «Цель проекта» | 0. Цель и образ результата |
| «Данные и материалы» | 2. Карта проекта |
| «Как работать» | 5. Протокол и режим работы |
| «Журнал» | 6. Память |
| «Запрещено» | 4. Запреты (добавить пометки) |

**2.2. Выберите образец.** В `agents_examples/` — пять заполненных файлов
для разных видов работы. Возьмите ближайший к вашей задаче и смотрите на
него, заполняя свой:

| Файл | Работа | Режим | Критерий готовности |
|---|---|---|---|
| `01_literature_review.md` | обзор литературы | конвейер | у каждой ссылки есть PDF и совпадает DOI |
| `02_peer_review.md` | рецензирование статьи | план и исполнение | разделы шаблона, ссылки на страницы, ≥5 проверенных утверждений |
| `03_data_processing.md` | обработка данных | ReAct | тесты на синтетике + сверка трёх значений с ручным расчётом |
| `04_parameter_search.md` | подбор параметров | поиск с метрикой | ошибка на контрольной задаче, которой агент не видел |
| `05_paper_writing.md` | текст статьи | план и исполнение | сборка, объём, каждое число есть в результатах |

**2.3. Заполните разделы 0, 1, 4, 5, 7.** Они описывают одну конкретную
задачу, которую агент может выполнить за 10–20 шагов. Разделы 2, 3, 6 — по
одной-две строки; подробно они пишутся на неделе 3.

- **0. Цель:** перечислите файлы, которые должны появиться, и их формат.
  «Проанализировать данные» — не цель; «`results/fit.csv` со столбцами
  `sample, k, k_err`» — цель.
- **1. Критерий готовности:** команда, см. 2.4.
- **4. Запреты:** не меньше трёх, у каждого пометка `[окно]`, `[вызов]`
  или `[среда]` (таблица в шаге 1.2). Хотя бы один закройте на деле:
  `chmod -R a-w data` или запуск агента с `--mode approve`.
- **5. Режим:** один из режимов лекции (слайды 30–33) и одна-две строки о
  порядке работы: когда вызывать проверку, что делать при её провале.
- **7. Бюджет:** число шагов и правило остановки («две неудачи проверки
  подряд — стоп и отчёт»).

**2.4. Проверка.** Критерий готовности — команда, которая возвращает код 0,
если результат правильный, и другой код, если нет. Возьмите
`check_template.py`, положите в свой проект как `checks/check.py` и
допишите проверки для своей задачи. Образцы — в папках `checks/` тестовых
проектов. Что можно проверить без агента:

| Дисциплина | Задача агенту | Что проверяет `checks/check.py` |
|---|---|---|
| Физика | оценить постоянную по таблице измерений, отметить выбросы | число строк результата совпадает с данными; постоянная совпадает с пересчётом двух строк вручную |
| Химия | молярные массы по списку формул | три значения сверены со справочником, расхождение меньше 0,01 |
| Биология | доля GC в последовательностях | пересчёт для одной последовательности независимым кодом |
| Науки о Земле | пересчёт координат станций | обратный пересчёт одной точки даёт исходные координаты |
| Математика | проверить неравенство на сетке параметров | граничные точки пересчитаны с повышенной точностью |
| Любая | сводка статьи в пять утверждений | у каждого утверждения есть номер страницы, и фраза найдена в тексте |

Запустите проверку дважды: на правильном результате (сделайте его сами или
возьмите проверенный) и на заведомо испорченном. Коды возврата должны
различаться. Держите проверку там, где агент её не изменит: закройте
`checks/` от записи (`chmod -R a-w checks`; чтобы поправить проверку самим —
`chmod -R u+w checks`) и запишите в разделе 4 запрет «не изменять
`checks/`» с пометкой `[среда]`.

**Чек-пойнт.** `python checks/check.py; echo $?` даёт 0 на правильном
результате и не 0 на испорченном; у всех запретов стоят пометки; коммит:

```bash
git add -A && git commit -m "AGENTS.md и проверка"
```

## Шаг 3. Прогон на своём проекте (45 мин)

1. Убедитесь, что всё закоммичено (`git status` пуст).
2. Запустите агента из папки проекта:
   ```bash
   ai4science run "Выполни цель из AGENTS.md."
   ```
   Если задача длиннее 10 шагов или затрагивает важные файлы, запускайте
   интерактивную сессию `ai4science --mode approve` и подтверждайте
   действия.
3. Проверьте результат своими руками: `python checks/check.py`, затем
   `git diff` — что изменил агент.
4. Запись в `diary.md` в форме недели 1: запрос, что сделал агент,
   результат, точка проверки (команда и её код), итог. Коммит.

Если проверка не прошла — не правьте результат руками. Запишите, что
пошло не так, уточните `AGENTS.md` (обычно раздел 0 или 2) и повторите
прогон.

**Чек-пойнт.** В `diary.md` — запись о прогоне с кодом проверки.

## Типовые ошибки

- **Два файла: `AGENT.md` и `AGENTS.md`.** Агент читает только первый —
  `AGENT.md`; новый файл не действует. Файл должен быть один.
- **Цель словами без файлов.** «Разобраться в данных» не проверяется.
  Нужны имена файлов и их содержимое.
- **Критерий готовности словами.** «Результат должен быть корректным» не
  проверяется. Нужна команда.
- **Проверка, которая не различает.** Возвращает 0 и на испорченном
  результате — значит, ничего не проверяет.
- **Проверку можно изменить.** Если агент может переписать `checks/`, код 0
  ничего не значит.
- **Проверку нельзя пройти честно.** Условие остановки должно быть
  достижимо правильной работой, иначе агент начнёт менять данные или
  проверку.
- **Все запреты `[окно]`.** Такой запрет меняет вероятность действия, но
  не делает его невозможным. Исходные данные закрываются на уровне
  `[среда]`.

## Артефакт недели 2

- **Что сделать:** описанный цикл «состояние → порождение → исполнение →
  новое состояние» своего проекта с разметкой по трём пространствам.
- **Форма:** `AGENTS.md` своего проекта: цикл описан разделами (цель и
  образ результата, критерий готовности, режим работы, остановка); запреты
  размечены по трём пространствам — окно, вызов, среда.
- **Минимум для «зачтено»:** разделы 0, 1, 4, 5, 7 заполнены; критерий
  готовности — исполняемая команда, различающая правильный и неправильный
  результат; не меньше трёх запретов с пометками, хотя бы один закрыт на
  уровне `[вызов]` или `[среда]`; в `diary.md` — сравнение двух прогонов на
  тестовом проекте и запись о прогоне на своём проекте с кодом проверки.
- **Идёт в:** домашнюю работу 1 «Среда и контекст» (сдача к неделе 6).
- **Время:** 3–4 ч.
- **Стартовый набор:** `test_projects/`, `AGENTS_template.md`,
  `agents_examples/`, `check_template.py`.
- **Где лежит у вас:** `AGENTS.md`, `checks/check.py`, `diary.md` в папке
  своего проекта.
- **Самопроверка:**
  1. в папке проекта один файл для агента: `ls AGENT.md AGENTS.md` находит
     только `AGENTS.md`;
  2. `python checks/check.py; echo $?` — 0 на правильном результате, не 0
     на испорченном;
  3. `grep -c '\[окно\]\|\[вызов\]\|\[среда\]' AGENTS.md` — не меньше 3;
  4. `touch data/x` завершается ошибкой доступа;
  5. `git log --oneline` показывает коммит с `AGENTS.md`.
- **Пример по дисциплинам:** тестовые проекты — физика и химия (спектры),
  науки о Земле (тренды), биология (обзор); образцы — биология, химия, науки
  о Земле, физика, математика.
- **Типовые ошибки:** дополняется после разбора на неделе 3.
