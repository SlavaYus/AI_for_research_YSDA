# AGENTS.md — подбор параметров (образец)

Физика: подбор шага и параметра сглаживания для численной модели теплопроводности.
Режим работы — поиск с метрикой: несколько попыток, выбор лучшей, откат остальных.

## 0. Цель и образ результата
Параметры `dt`, `alpha_smooth`, при которых ошибка относительно аналитического
решения минимальна при времени расчёта до 60 с.

В конце в проекте существуют:
- `results/search.csv` — все попытки: `dt, alpha_smooth, error_L2, time_s, git_tag`;
- `config/best.yaml` — лучшие параметры;
- метка git `best-<дата>` на коммите с лучшими параметрами.

Ничего больше создавать не надо.

## 1. Критерий готовности
```
python checks/evaluate.py config/best.yaml
```
Проверка заново считает `error_L2` на контрольной задаче, которой нет в
`results/`, и возвращает 0, если ошибка меньше 1e-4, а время — меньше 60 с.

## 2. Карта проекта и источники
`src/solver.py` — решатель, менять нельзя. `config/` — параметры.
Агент не знает сам: при `dt > 1e-3` схема неустойчива.

## 3. Инструменты и границы
Запуск решателя с параметрами, запись в `config/` и `results/`, git-ветки и метки.

## 4. Запреты
1. Не менять `src/solver.py` и `checks/`. `[среда]` — права только на чтение.
2. Не подбирать параметры по контрольной задаче. `[среда]` — её файлов нет в рабочей копии.
3. Не удалять строки из `results/search.csv`. `[окно]`

## 5. Протокол работы
Режим — поиск по дереву с бюджетом:
1. каждая попытка — отдельная ветка `try/<dt>-<alpha>`;
2. метрика — `error_L2` на обучающей задаче; строка в `results/search.csv`;
3. после бюджета — лучшая попытка в `main`, остальные ветки остаются для истории.

## 6. Память
`results/search.csv` — дописывается; `diary.md` — почему выбран диапазон поиска.

## 7. Остановка и эскалация
- Бюджет: 24 попытки или 2 ч расчёта.
- Улучшение меньше 1 % за 6 попыток подряд — стоп.
- Все попытки неустойчивы — стоп, спросить человека.
