# AGENTS.md — текст статьи (образец)

Математика: статья 2–4 стр. о численной проверке неравенства на сетке параметров.
Режим работы — план и исполнение: структуру утверждает автор, текст пишется по разделам.

## 0. Цель и образ результата
Рукопись по шаблону конференции курса, собранная в PDF.

В конце в проекте существуют:
- `paper/main.tex` и `paper/main.pdf` — не больше 4 стр.;
- в тексте у каждого фрагмента пометка `[написано]`, `[порождено]` или `[источник]`.

Ничего больше создавать не надо.

## 1. Критерий готовности
```
latexmk -pdf paper/main.tex && python checks/check_paper.py paper/
```
Сборка без ошибок; проверка возвращает 0, если PDF не длиннее 4 стр., каждое
число в тексте есть в `results/*.csv`, каждая ссылка есть в `paper/refs.bib`,
а пометки авторства стоят у всех абзацев.

## 2. Карта проекта и источники
`results/` — результаты расчёта, только чтение. `paper/refs.bib` — литература.
Агент не знает сам: какие результаты автор считает главными — `paper/outline.md`.

## 3. Инструменты и границы
Чтение `results/`, запись в `paper/`, сборка LaTeX.

## 4. Запреты
1. Не писать числа, которых нет в `results/`. `[окно]` — ловит проверка из раздела 1.
2. Не добавлять ссылки, которых нет в `refs.bib`. `[окно]` — ловит проверка.
3. Не менять `results/`. `[среда]` — права только на чтение.
4. Не указывать имена авторов: подача обезличенная. `[окно]`

## 5. Протокол работы
Режим — план и исполнение: план разделов → подтверждение автора → раздел →
сборка и проверка → коммит. Раздел «Ограничения» пишет автор.

## 6. Память
`paper/CHANGES.md` — что изменено в каждой версии и по чьей правке.

## 7. Остановка и эскалация
- Бюджет: 20 шагов на раздел.
- Текст длиннее 4 стр. — не сокращать самовольно, спросить автора, что убрать.
- Две неудачи проверки подряд по одной причине — стоп и отчёт.
