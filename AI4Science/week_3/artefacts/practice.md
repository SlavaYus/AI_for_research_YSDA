# Неделя 3. Самостоятельная практика: сжатие статьи, AGENTS.md и файл-указатель

Курс «ИИ-ассистенты для исследователя. AI4Science».

**Результат недели:** в вашем проекте лежат сжатие статьи на трёх уровнях
со сверкой утверждений (`memory/L1.md`, `memory/L2.md`, `memory/L3.md`),
полный `AGENTS.md` с разделом «Чего агент не может знать сам» и файл-указатель
`INDEX.md`; всё закоммичено в git.

**Время:** 3,5–5 часов.

**Что нужно заранее:**
- учебный агент: `ai4science doctor` проходит без ошибок;
- проект в git-репозитории с `AGENTS.md` (заполнены разделы 0, 1, 4, 5, 7)
  и `diary.md`;
- статья в PDF: своя или основная статья вашего проекта, 8–30 страниц;
- Python 3 с пакетами numpy и pytest;
- `pdftotext` из пакета poppler: `brew install poppler` на macOS,
  `sudo apt install poppler-utils` в Ubuntu и WSL. Без него:
  `python3 -m pip install pypdf`.

Все команды выполняются в терминале Linux, macOS или WSL.

## Что вы делаете и зачем

Окно контекста — всё, что модель видит на одном шаге: системный промпт,
`AGENTS.md`, описания инструментов, запрос, вывод инструментов, прочитанные
файлы. Окно конечно, и сведения в нём используются неравномерно: хуже всего —
в середине длинного окна. Длинную работу держат в границах окна тремя
способами: **сжать**, **вынести** из окна в файлы, **разделить** на
подзадачи в отдельных окнах. На этой неделе вы применяете все три к своему
проекту:

| Способ | Что вы делаете | Файлы |
|---|---|---|
| сжать | каскадное сжатие статьи L1 → L2 → L3 и сверка тезисов с оригиналом | `memory/L1.md`, `L2.md`, `L3.md` |
| разделить | каждая часть статьи сжимается отдельным запуском агента | `cascade.sh` |
| вынести | разделы 2, 3, 6 в `AGENTS.md`, файл-указатель, файл состояния, пометки в коде | `AGENTS.md`, `INDEX.md`, `STATUS.md` |

**Уровни сжатия:**
- **L1** — реферат по разделам или частям статьи: 100–150 слов на часть,
  числа дословно, у каждого утверждения — страница;
- **L2** — 5–10 тезисов всей статьи, каждый — проверяемое утверждение со
  страницей;
- **L3** — главный результат одной строкой.

**Сверка** — проверка тезиса по оригиналу: страница и дословная цитата.
Каждый уровень сжатия — порождённый текст: он теряет условия, обобщает,
путает числа. Сверка находит такие ошибки до того, как агент начнёт
опираться на `L2.md` в следующих сессиях.

## Шаг 2. Статья в окне и каскадное сжатие (90 мин)

### 2.1. Статья целиком в окне (15 мин)

Сначала посмотрите, сколько места статья занимает в окне и как агент
отвечает по её середине.

```bash
pdftotext paper/paper.pdf paper/paper.txt
wc -w paper/paper.txt
ai4science --no-lean
```

В сессии:
1. «Прочитай paper/paper.txt целиком.»
2. `/status` — запишите заполнение окна.
3. Три вопроса о деталях из середины статьи: число, условие опыта,
   ограничение метода. Ответы на них вы знаете или найдёте по PDF.
4. `/exit`.

Запишите в `diary.md` число токенов в окне и три ответа агента. Верны ли
ответы, вы проверите в шаге 2.4.

### 2.2. Каскадное сжатие (20 мин, из них 10–15 мин работает агент)

```bash
bash cascade.sh paper/paper.pdf
```

Что делает скрипт:
1. Извлекает текст статьи с разбиением по страницам.
2. Режет его на части по ~1500 слов (подряд идущие страницы) в
   `paper/parts/`; в каждой части метки `[с. N]`.
3. Сжимает каждую часть **отдельным** запуском `ai4science run` — в своём
   окне — в `memory/L1/part_NN.md` и склеивает их в `memory/L1.md`.
4. По `L1.md` в новом окне составляет `memory/L2.md` и добавляет пустую
   таблицу сверки; по `L2.md` — `memory/L3.md`.

Если агент не записал какую-то часть, запустите скрипт ещё раз: готовые
части он пропускает. Если статья уже разбита на разделы — например, из
исходников LaTeX, — положите их в `paper/sections/` файлами `.md`: скрипт
сожмёт разделы вместо частей по страницам. Номера страниц в них поставьте
метками `[с. N]`.

Скрипт — одна из возможных реализаций. Каскад можно выполнить и вручную в
сессии агента или в чате с моделью — важно, чтобы каждый уровень строился
только по предыдущему, а у утверждений оставались страницы.

### 2.3. Чтение уровней (15 мин)

1. В `memory/L1.md` заполните строку «Статья:»: авторы, название, издание,
   год, DOI или arXiv с версией.
2. Прочитайте L1, L2 и L3. Удалите из L2 тезисы без страницы и общие фразы
   без содержания («авторы провели исследование»). L3 должна называть
   результат; название статьи результатом не является.

### 2.4. Сверка (35 мин)

Это главная часть шага. Откройте PDF и `memory/L2.md` рядом. Выберите
**не меньше трёх** тезисов: тезис с самым конкретным числом, тезис с общим
словом («всегда», «во всех», «значительно») и тезис, в котором вы
сомневаетесь. Для каждого:

1. Найдите место в статье по странице из тезиса. Сверяйте по PDF: `L1.md` —
   тоже порождённый текст.
2. Скопируйте цитату дословно, на языке оригинала. Номер страницы — номер в
   программе просмотра PDF, не номер страницы журнала.
3. Заполните строку таблицы: номер тезиса, страница, цитата, итог.
4. Если тезис расходится с цитатой — исправьте тезис и запишите в итоге,
   что именно расходилось.

Типичные ошибки сжатия, которые находит сверка:

| Ошибка | Пример |
|---|---|
| обобщение | в статье «помогает в одной задаче из двух» → в тезисе «помогает во всех задачах» |
| потерянное условие | «устойчиво при длине входа до 2048 токенов» → «устойчиво» |
| перепутанные числа | значение из другой строки таблицы или другого опыта |
| причина вместо корреляции | «X связан с Y» → «X вызывает Y» |
| чужая мысль | утверждение из обзора литературы подано как результат авторов |

Образец — `example_memory/L2.md`: тезис 4 в черновике звучал «вопрос до и
после данных устраняет эффект во всех задачах»; в статье приём помогает в
извлечении по ключу и почти не меняет картину в вопросах по документам.

Вернитесь к трём ответам агента из шага 2.1: сверьте их по PDF и допишите
итог в `diary.md`.

## Шаг 3. AGENTS.md целиком (45 мин)

До этого шага в `AGENTS.md` подробно описана задача (разделы 0, 1, 4, 5, 7),
а разделы 2, 3, 6 — одной-двумя строками. Теперь они описывают проект.

1. Откройте `AGENTS_sections_2_3_6.md` и перенесите его разделы 2, 3, 6 в
   свой `AGENTS.md` вместо коротких. Образец заполнения —

2. **«Чего агент не может знать сам»** — не меньше трёх строк: единицы и

   результата. Примеры по дисциплинам — в конце `AGENTS_sections_2_3_6.md`.
3. Правило строки: для каждой строки всего файла спросите — если её убрать,
   ошибётся ли агент? Если нет, удалите строку.
4. Создайте `STATUS.md` по образцу из `AGENTS_sections_2_3_6.md`: где работа,

**Проверка на деле (10 мин).** Выберите задачу своего проекта, в которой
важна одна из строк «Чего агент не может знать сам». Запустите агента на
двух копиях проекта: с этой строкой и без неё.

```bash
cp -r . /tmp/with && cp -r . /tmp/without
# в /tmp/without/AGENTS.md удалите выбранную строку
cd /tmp/with && ai4science --no-lean run "<задача>"
cd /tmp/without && ai4science --no-lean run "<задача>"
```

Запишите оба ответа в `diary.md`. Если ответ не изменился, посмотрите в
выводе, откуда агент взял сведения. В `example_project` так и происходит:
без строки о серии 2024-03 агент всё равно получает 51,66 кДж/моль — он
прочитал `data/README.md` по указателю и запустил `src/report.py`, где серия
исключена в коде. Строка в `AGENTS.md` там защищает только новый код, который
агент напишет сам; нужна ли такая строка, решает исследователь.

**Чек-пойнт.** `python3 check_week3.py --no-git`: в блоке «AGENTS.md» все
строки «[OK]».

## Шаг 4. Файл-указатель и пометки в коде (30 мин)

1. **`INDEX.md`** в корне проекта: по строке на важный файл или папку —
   путь в обратных кавычках и что в нём. Образец —
   `example_project/INDEX.md`. Включите `memory/L2.md` — сжатие статьи, к
   которому агент обращается вместо PDF.
2. В разделе 2 `AGENTS.md` — ссылка: «Где что лежит — в `INDEX.md`. Прочитай
   его первым».
3. **Пометки в коде.** В строках документации 2–3 главных функций укажите:
   откуда данные, чем проверена, где используется. Образец —
   `example_project/src/physics.py`. Пометки может написать и агент:

   ```bash
   ai4science --no-lean run "В строки документации функций в src/ добавь три пометки: \
   'Данные:', 'Проверка:', 'Используется в:' — с путями вида файл::функция. \
   Код функций не меняй."
   ```

   Проверьте `git diff`: изменились только строки документации.
4. **Проверка указателя.** В новом окне спросите агента о месте в проекте:

   ```bash
   ai4science --no-lean run "Прочитай INDEX.md. В каком файле и какой функции \
   вычисляется <ваша величина>? Ответь путём и именем функции; другие файлы \
   открывай, только если без них не ответить."
   ```

   Посчитайте блоки `▸` в выводе: каждый — один вызов инструмента. Ответ за
   2–3 вызова означает, что указатель работает.

```bash
python3 check_week3.py
git add -A && git commit -m "AGENTS.md целиком, INDEX.md, STATUS.md, пометки в коде"
python3 check_week3.py
```

Второй запуск проверки нужен после коммита: блок «git» проверяет, что всё
закоммичено.

**Чек-пойнт.** Последняя строка вывода — «Все обязательные пункты
выполнены»; код возврата 0.

## Типовые ошибки

- **L1 без страниц.** Без страниц сверка превращается в поиск по всей статье.
- **Сверка по L1.** L1 — порождённый текст; ошибка сжатия в L1 переходит в
  L2 и подтверждается сама собой. Сверка — только по PDF.
- **Цитата пересказом или переводом.** Цитата — дословный фрагмент
  оригинала; `check_week3.py` ищет её в тексте статьи.
- **L2 из общих слов.** «Метод показал хорошие результаты» не проверяется.
  В тезисе — число, условие или ограничение.
- **L3 — название статьи.** L3 называет результат.
- **«Чего агент не может знать сам» пересказывает код и README.** Агент
  увидит это сам; строки занимают окно на каждом вызове.
- **Указатель устарел.** Файл переименовали, а строка в `INDEX.md` осталась:
  агент пойдёт по неверному пути. `check_week3.py` проверяет, что все пути из
  указателя существуют.
- **`STATUS.md` как второй журнал.** Файл перезаписывается целиком: в нём
  только текущее состояние. История — в `diary.md`.
- **Два файла `AGENT.md` и `AGENTS.md`.** Агент читает только первый; файл
  должен быть один.

## Артефакт недели 3

- **Что сделать:** трёхуровневое сжатие своей статьи со сверкой утверждений;
  рабочий `AGENT.md` и файл-указатель для своего проекта. В курсе файл агента
  называется `AGENTS.md`; в силлабусе — `AGENT.md`; это один файл.
- **Минимум для «зачтено»:** уровни L1 → L2 → L3; не меньше трёх тезисов L2
  сверены с оригиналом — страница и дословная цитата; `AGENTS.md` — не меньше
  пяти разделов, есть раздел «Чего агент не может знать сам»; файл-указатель
  `INDEX.md`, все пути в нём существуют; всё в git.
- **Идёт в:** домашнюю работу 1 «Среда и контекст» (сдача к неделе 6).
- **Время:** 3,5–5 ч.
- **Стартовый набор:** `cascade.sh`, `memory_template/`, `example_memory/`,
  `AGENTS_sections_2_3_6.md`, `example_project/`, `check_week3.py`,
  `agent_notebook/`.
- **Где лежит у вас:** `memory/L1.md`, `memory/L2.md`, `memory/L3.md`;
  `AGENTS.md`, `INDEX.md`, `STATUS.md` в корне проекта; записи в `diary.md`.
- **Самопроверка:**
  1. `python3 check_week3.py; echo $?` — последняя строка «Все обязательные
     пункты выполнены», код 0;
  2. `grep -c '^## ' AGENTS.md` — не меньше 5;
  3. `grep -i 'не может знать сам' AGENTS.md` находит заголовок раздела;
  4. `grep -c '^| [0-9]' memory/L2.md` — не меньше 3 строк сверки;
  5. `git status --short memory AGENTS.md INDEX.md` — пустой вывод.
- **Пример по дисциплинам:**

  | Дисциплина | Статья для сжатия | Строка «Чего агент не может знать сам» | Строка `INDEX.md` |
  |---|---|---|---|
  | Физика | статья о методе измерения, на котором построен проект | «время в серии 2025-02 — в микросекундах» | `analysis/calib.py` — калибровка детектора |
  | Химия | своя статья о кинетике реакции (образец — `example_project/`) | «температура в `data/raw/` — в градусах Цельсия; серию 2024-03 не использовать» | `src/physics.py` — формулы, `fit_arrhenius()` |
  | Биология | статья о методе секвенирования, на котором построен проект | «образцы S7 и S8 перепутаны: верные метки — в `samples.tsv`» | `pipeline/qc.smk` — контроль качества прочтений |
  | Науки о Земле | статья о гомогенизации рядов наблюдений | «станцию C в 2019 г. перенесли на 40 м выше; пропуск — −9999» | `data/stations.csv` — координаты и высоты станций |
  | Математика | статья, на результат которой опирается доказательство | «в статье преобразование Фурье с 2π в показателе, в коде — без» | `notes/lemmas.md` — леммы и статус доказательств |

- **Типовые ошибки:** дополняется после разбора на следующей лекции.
