# AGENT.md — SASRec_exp: сравнение оптимизаторов и Lipschitz-регуляризации

Файл-договор с агентом. Агент читает его в начале каждой сессии.
Тот же договор у других агентов называется `AGENTS.md`, `CLAUDE.md`, `.cursorrules`.

## Цель проекта
Исследовать, как выбор оптимизатора (AdamW против Muon, где Muon обновляет 2D
веса attention/FFN, а AdamW — 1D веса и эмбеддинги), глубина SASRec (число
трансформерных блоков 2/4/6) и Lipschitz-регуляризация attention-слоя
(W <- W/sigma_max(W) перед каждым forward) влияют на качество и покрытие
рекомендаций на датасетах Beauty и Yambda. Результат — метрики HR@10,
NDCG@10, Coverage@10 (общие и по бакетам пользователей/айтемов) и итоговый
barplot.

## Данные и материалы
- `data/` — симлинки на готовые данные и сплиты: `Beauty` (родительский SemantID),
  `Yambda` (NFS-путь). Сплит `leave-one-out-no_cold_items` получен
  LeaveOneOutSplitter (код скопирован в `src/split.py`).
- `src/` — весь код экспериментов (скопированные из родительского репо
  sasrec/split/datasets/sce + собственные optimizers/lipschitz/metrics/train/
  experiment/run_experiments/plot_results).
- `results/` — json по каждому прогону + логи обучения в `results/logs/`.
- `figures/` — итоговые графики.
- Исходные данные не изменять; производные файлы — в `results/`, `figures/`.

## Как работать
- Код — в `src/`, запускать перед тем, как сообщать результат.
- Драйвер: `CUDA_VISIBLE_DEVICES=5 nohup python -m src.run_experiments --stage all
  > results/logs/sweep.log 2>&1 &` (завершенные прогоны пропускаются).
- Каждый вывод сопровождается способом его проверки.
- Сводки и заметки для следующих сессий — в `memory/` (пока не создана).

## Журнал
- После каждой задачи — запись в `diary.md`: дата, запрос, что сделано,
  результат, точка проверки, итог проверки. Старые записи не менять.
- Каждый обучающий прогон автоматически дописывает свою секцию в `diary.md`
  (делает `src/experiment.py:log_to_diary`).
